# 팀 편성 웹 앱 구현 계획

> 실행 방법: 이 계획을 위에서부터 과제(Task) 하나씩 실행한다. 단계마다 `- [ ]`를 체크하며 진행한다.

**목표:** 학생이 팀에 지원하고 팀원이 투표로 받아들이며, 마감 뒤 팀이 없는 학생을 AI가 배정하고 앱이 규칙으로 검사하는 Streamlit 웹 앱을 만들어 Streamlit Community Cloud에 배포한다.

**구조:** 규칙 판단(`teamapp/rules.py`, `teamapp/solver.py`)은 DB와 화면을 모르는 순수 파이썬으로 만들어, DB 없이 단위 테스트한다. 쓰기 처리(`teamapp/actions.py`)는 저장소 인터페이스(`Repo`)에만 의존하므로, 테스트에서는 메모리 저장소로, 앱에서는 PostgreSQL 저장소(`teamapp/db.py`)로 같은 코드를 실행한다. 화면(`streamlit_app.py`)은 이 함수들을 부르고 결과만 그린다.

**기술:** Python 3.13, Streamlit 1.66.0, psycopg2-binary, bcrypt, requests, python-dotenv, Supabase(PostgreSQL, Session pooler), 오픈라우터 무료 모델, GitHub Actions(DB 일시정지 막기), 표준 라이브러리 `unittest`

**설계 문서:** `docs/PRD.md` (이 계획은 PRD를 근거로 함. 실행할 때 둘 다 읽음)

## 작업 방식

- 코드는 Claude가 작성해 수강생 컴퓨터의 `C:\Users\user\team-formation`에 넣는다. 테스트 실행, 앱 실행, 커밋, 푸시는 수강생이 PowerShell에서 한다.
- DB와 Streamlit이 필요 없는 테스트(과제 1~6)는 Claude의 작업 공간에서도 먼저 돌려 통과를 확인한 뒤 넘긴다.
- PowerShell 명령은 모두 저장소 폴더에서 실행한다: `cd $HOME\team-formation`
- 가상 환경은 활성화하지 않고 `.venv\Scripts\python`으로 직접 부른다(PowerShell 실행 정책 문제를 피함).
- 테스트 명령(이하 "전체 테스트"): `.venv\Scripts\python -m unittest discover -s tests -t . -v`
  - DB가 필요한 테스트는 `.env`에 `DATABASE_URL`이 없으면 건너뛴다. Streamlit 화면 테스트는 Streamlit이 없으면 건너뛴다.
  - DB 테스트와 화면 테스트는 Supabase의 tf_ 데이터를 지우고 명단을 다시 올린다. 채점 전 상태와 상관없으므로 괜찮지만, 배포 앱으로 시험하는 도중에는 돌리지 않는다.

## 전체 제약 (모든 과제에 적용)

- 화면 key는 PRD 5.4절 표와 글자 하나까지 같게 쓴다: `login_student_no`, `login_password`, `login_submit`, `whoami`, `result`, `team_{팀 번호}`, `apply_{팀 번호}`, `vote_yes_{지원자 학번}`, `vote_no_{지원자 학번}`, `admin_roster_file`, `admin_team_count`, `admin_start`, `admin_close`, `unassigned`, `admin_assign`, `assign_status`, `admin_confirm`. `refresh`는 만들지 않는다.
- 결과 안내 문구는 `승인`, `대기`, `거절`, `막힘` 가운데 하나와 `": "`로 시작한다.
- 역할 문자열은 정확히 `기획자`, `웹 프로그래머`, `프론트엔드 디자이너`, `테스터`, `보고서 작성자`, `발표자`이다. 약자는 PL, WP, FD, TT, RW, PT.
- 팀 인원은 2~4명, 필수 포함 역할은 `기획자`와 `웹 프로그래머`이다.
- 테이블 이름은 모두 `tf_`로 시작한다.
- 학생 이름, 학번, 지원 순서를 보고 결과를 정하는 코드는 쓰지 않는다(감점 19번). 판단은 역할과 규칙으로만 한다.
- 비밀 값 `DATABASE_URL`, `OPENROUTER_API_KEY`, `ADMIN_PASSWORD`는 `.env`(로컬)와 Streamlit Secrets(배포)에서만 읽는다. 값을 화면, 로그, 오류 메시지에 출력하지 않는다. 있는지 확인할 때는 "있음/없음"만 출력한다.
- 비밀번호는 bcrypt(rounds=10)로 해시해 저장한다.
- AI 모델은 `google/gemma-4-31b-it:free`(1차), `nvidia/nemotron-3-super-120b-a12b:free`(2차), `poolside/laguna-s-2.1:free`(3차). `openrouter/free`는 쓰지 않는다. 모델마다 전체 대기 시간 120초.
- 자동 새로 고침 간격은 3초(`REFRESH_SECONDS = 3`).
- CSV는 `utf-8-sig`로 읽는다.
- 화면의 시각은 한국 시간(UTC+9, `timezone(timedelta(hours=9))`)으로 보여 준다. Windows에서 시간대 데이터가 없어도 되도록 `zoneinfo`는 쓰지 않는다.

## 검토 초점 (테스트가 따로 붙지 않으면 놓치기 쉬운 경우)

1. 3초마다 화면이 다시 그려지는 사이에 같은 단추를 두 번 누름 → 두 번째 지원은 "막힘: 결과를 기다리는 지원이 있음"이고 지원은 하나만 생겨야 함. 과제 5의 `test_double_apply_is_blocked`가 확인함.
2. 관리자가 명단을 다시 올려 로그인해 있던 학생이 명단에서 사라짐 → 그 학생 화면은 오류 없이 로그인 화면으로 돌아가야 함. 과제 8의 `test_removed_student_is_logged_out`이 확인함.
3. CSV에 빈 줄, 줄 끝 CRLF, BOM, 칸 앞뒤 공백이 있음 → 정상으로 읽어야 함. 과제 3의 `test_tolerates_blank_lines_crlf_and_spaces`가 확인함.
4. AI가 JSON을 코드 블록(```json)으로 감싸거나 팀을 `"팀2"`처럼 문자열로 줌 → 배정안으로 읽어야 함. 과제 6의 `test_parse_accepts_code_fence_and_team_text`가 확인함.
5. 배포한 앱이 잠들었다 깨어나거나 풀러가 연결을 끊음 → 끊어진 연결을 버리고 새로 연결해 화면이 열려야 함. 과제 7의 `test_broken_connection_is_replaced`가 확인함.

### 과제 1: 저장소 준비와 역할 계산

**Files:**

- 이미 있음: `.gitignore`, `.env`(커밋하지 않음)

**Interfaces:**
- Produces (`teamapp/rules.py`):
  - 상수 `ROLES: tuple[str, ...]`(위 6개, 이 순서), `ABBR: dict[str, str]`(역할→약자), `PLANNER = "기획자"`, `WEB = "웹 프로그래머"`, `TEAM_MIN = 2`, `TEAM_MAX = 4`, `PENDING = "대기"`, `APPROVED = "승인"`, `REJECTED = "거절"`, `BLOCKED = "막힘"`, `YES = "찬성"`, `NO = "거부"`
  - `@dataclass(frozen=True) class Student: id: int; student_no: str; name: str; main_role: str; sub_roles: tuple[str, ...] = ()` 와 메서드 `can(role: str) -> bool`
  - `required_filled(members: Sequence[Student]) -> int`: 기획자와 웹 프로그래머를 서로 다른 학생에게 맡길 때 채울 수 있는 최대 수(0~2)
  - `unmet_roles(members: Sequence[Student]) -> list[str]`: 아직 못 채운 필수 역할의 설명. 기획자를 맡을 학생이 없으면 `"기획자"`, 웹 프로그래머를 맡을 학생이 없으면 `"웹 프로그래머"`, 둘 다 맡을 수 있는 학생이 한 명뿐이라 하나만 채우면 `"기획자나 웹 프로그래머 중 하나"`
  - `seat_problem(members_after: Sequence[Student]) -> str | None`: 지원자를 넣은 뒤의 팀원 목록을 받아, 어기는 규칙이 있으면 이유, 없으면 `None`. 검사 순서와 문구는 아래 테스트가 정함

- [ ] **단계 1: 실패하는 테스트 작성** (`tests/test_rules.py`)

```python
def S(i, main, *subs):  # 테스트용 학생
    return Student(i, f"2026{i:03d}", f"학생{i}", main, tuple(subs))

def test_one_student_who_can_do_both_fills_only_one():
    assert required_filled([S(1, "기획자", "웹 프로그래머")]) == 1
    assert unmet_roles([S(1, "기획자", "웹 프로그래머")]) == ["기획자나 웹 프로그래머 중 하나"]

def test_sub_role_counts_for_required():
    assert required_filled([S(1, "테스터", "기획자"), S(2, "프론트엔드 디자이너", "웹 프로그래머")]) == 2

def test_seat_problem_full_team():
    four = [S(1,"기획자"), S(2,"웹 프로그래머"), S(3,"테스터"), S(4,"발표자")]
    assert seat_problem(four + [S(5, "보고서 작성자")]) == "팀이 꽉 참"

def test_seat_problem_same_main_role():
    assert seat_problem([S(1,"기획자"), S(2,"기획자")]) == "같은 주 역할의 팀원이 있음"

def test_seat_problem_not_enough_seats_for_required():
    # 공고 3장 예: 테스터와 발표자만 있는 팀(2명)에 보고서 작성자가 지원
    msg = seat_problem([S(1,"테스터"), S(2,"발표자"), S(3,"보고서 작성자")])
    assert msg == "필수 포함 역할 자리가 모자람 (남는 자리 1개, 채워야 할 역할: 기획자, 웹 프로그래머)"

def test_seat_problem_ok_when_seats_enough():
    assert seat_problem([S(1,"테스터"), S(2,"기획자")]) is None
```

### 과제 2: 지원·투표·마감 판단

**Files:**
- Modify: `teamapp/rules.py`
- Test: `tests/test_rules.py`

**Interfaces:**
- Consumes: 과제 1의 상수, `Student`, `seat_problem`
- Produces (`teamapp/rules.py`):
  - `@dataclass(frozen=True) class Application: id: int; team_id: int; student_id: int; status: str; reason: str = ""; created_at: datetime | None = None`
  - `@dataclass(frozen=True) class State: students: dict[int, Student]; team_ids: tuple[int, ...]; members: dict[int, tuple[int, ...]]; applications: tuple[Application, ...]; votes: dict[int, dict[int, str]]; closed: bool`
    - 메서드: `team_name(team_id) -> str`(`"팀{n}"`), `team_of(student_id) -> int | None`, `team_members(team_id) -> list[Student]`, `pending_of(student_id) -> Application | None`, `application(app_id) -> Application | None`, `pending_for_team(team_id) -> list[Application]`(지원 순서), `unassigned() -> list[Student]`(학번 순)
  - `@dataclass(frozen=True) class Outcome: kind: str; message: str` 와 속성 `text -> str`(`f"{kind}: {message}"`)
  - `apply_lock_reason(state, student_id) -> str | None`: 지원 단추를 모두 비활성화할 이유(마감, 팀 있음, 대기 지원 있음). 화면이 씀
  - `decide_apply(state, student_id, team_id) -> Outcome`
  - `@dataclass(frozen=True) class VoteDecision: outcome: Outcome; record_vote: bool; final_status: str | None`
  - `decide_vote(state, application_id, voter_id, vote) -> VoteDecision`: `state`는 이번 투표를 넣기 전 상태
  - `decide_close(state) -> tuple[Outcome, tuple[int, ...], tuple[int, ...]]`: (결과, 거절할 대기 지원 id들, 팀에서 뺄 학생 id들)
